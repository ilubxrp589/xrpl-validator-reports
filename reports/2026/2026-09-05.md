## Engine findings fixed

- **fix(xrpl-ledger): F181 — a holder-less sender ISSUES to the issuer within its limit** (`30d4e7a`, xrpl-validator)
  `apply_iou_direct` sized the sender's leg by `available()` — the sender's HOLDINGS of the issuer's IOU — so a sender holding none was tecPATH_DRY. rippled's sender hop is `DirectStepI::maxPaymentFlow` (DirectStep.cpp:476-490): when `srcOwed <= 0` the hop ISSUES the sender's own IOU up to `creditLimit2(dst, src) + srcOwed`, the issuer's trust limit toward the sender less what the sender already owes it.

- **fix(xrpl-ledger): F183 — a strand's spend is the walk's own figure, not the line's quantised delta** (`5449dfa`, xrpl-validator)
  `strand_pass` measured what a strand spent by differencing the sender's line before and after, trusting the walk's own figure only when the two agreed to 1e-9 relative. A trust line holds 16 significant digits on its MAGNITUDE, so the delta is the true spend quantised to the balance's ulp — for a small spend from a large line that quantum dwarfs the relative test and the exact figure was refused. rippled never reads …
- **fix(xrpl-ledger): F184 — an autobridged leg crosses the taker's own offer** (`199e7d4`, xrpl-validator)
  The self-cross rule (`BookOfferCrossingStep::limitSelfCrossQuality`, BookStep.cpp:402-445) removes the taker's own offer only on the DEFAULT path — `defaultPath_ && offer.quality() >= qualityThreshold_ && owner == strandSrc == strandDst` — so on an autobridged leg the taker's own offer is crossed like any other maker's, its self-transfers netting to nothing (`accountSend` with sender == receiver is a no-op).
