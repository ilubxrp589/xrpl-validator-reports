### Other engineering changes

- **feat(ledger): NFTokenMint carrying Amount also rests a sell offer** (`2488343`, xrpl-validator)
  featureNFTokenMintOffer: a mint with `Amount` mints the token AND rests a sell offer in one transaction. rippled factors this as `nft::tokenOfferCreateApply` and calls it from both NFTokenCreateOffer and NFTokenMint (NFTokenMint.cpp:312-330). We minted but never created the offer, losing exactly three mutations every time — the NFTokenOffer, its sell-offer directory page, and the owner directory entry. 11 cases in …
- **fix(ledger): AMMWithdraw by LPTokenIn pays out both pool assets** (`e7b7d4d`, xrpl-validator)
  tfLPToken (0x00010000) withdrawals name only how many LPTokens to redeem and receive BOTH pool assets in proportion — the transaction carries no Amount or Amount2 at all. Our apply path only ever moved Amount/Amount2, found neither, and so burned the LP tokens while paying out nothing. That is exactly why every case was missing the two RippleStates and the AccountRoot a payout touches.
- **fix(ledger): pass the page hint when a payment tears down a trust line** (`95eb59c`, xrpl-validator)
  A line spent to zero mid-payment reverts to default and is deleted, which must remove it from BOTH owner directories. We called owner_dir_remove for both sides but passed None as the page hint, while TrustSet's trustDelete passes the real LowNode/HighNode (trust_set.rs:371-375).
- **fix(ledger): a bridge leg with a pool but no book carries nothing** (`413368a`, xrpl-validator)
  All 8 cases were Flags=65536 exactly — tfPassive, buy side, IOU<->IOU with no XRP leg — so every one takes the auto-bridge path. That uniformity is what made the cluster tractable.
- **fix(probe): hydrate the ISSUERS' owner directories for OfferCreate** (`e10fe45`, xrpl-validator)
  A crossing OfferCreate can hand the taker an IOU it has never held, creating a trust line that appends to BOTH sides' owner directories. The probe hydrated only the ACCOUNT's, never the issuers' — so for a real issuer, whose directory runs to thousands of pages, dir_insert could not see the existing directory and invented a fresh root where mainnet modified a tail page.
