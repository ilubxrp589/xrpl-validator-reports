## Engineering changes

- **fix(sync): skip retry+full-scan on mismatch, just log and move on** (`a779791`, xrpl-validator)
  The 3x retry + 5min full scan never healed a real divergence - it only helped with transient rippled RPC staleness. In practice it blocked sync for 5+ minutes after every mismatch, preventing any further mismatches from being captured for diagnosis.
- **fix(sync): update hasher during fast-path gap catchup** (`5957491`, xrpl-validator)
  ROOT CAUSE FOUND: When ws_sync falls behind (network closed multiple ledgers since our last sync), it processes gap ledgers via "fast path" which writes to state.rocks but skips the hash check. The fast path updated leaf_cache (used only for disk persistence) but did NOT update the live hasher.
- **perf(sync): hash-check every ledger + add per-stage timing** (`4f2122c`, xrpl-validator)
  Fix #1: force compute_hash=true on every ledger. Previously only the last ledger in a gap-catchup batch got hash-verified, so the validation match count was capped by the "catch up to tip" rate. Now every ledger applied is a ledger verified.
- **fix(sync): fetch account_hash for every ledger, not just batch tail** (`6cc3fb6`, xrpl-validator)
  compute_hash was always true after the last fix, but account_hash was still only populated when process_seq == closed_seq. Gap ledgers computed their hash and had nothing to compare against — so no MATCH/MISMATCH log fired and shadow hash stayed at 0.
