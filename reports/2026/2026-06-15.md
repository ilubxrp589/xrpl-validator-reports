## Engineering changes

- **feat(validator): regenerate amendment vote list for rippled 3.2.0** (`7f15b90`, xrpl-validator)
  Regenerated supported_amendments() from 3.2.0 features.macro (Supported::Yes, 46): drops the amendments 3.2.0 retired into baseline, adds the new supported 3.2.0 amendments (LendingProtocol/TokenEscrow/PermissionedDEX/SingleAssetVault/DynamicNFT/ MPTokensV1 + fixes), and excludes the 5 Supported::No placeholders (MPTokensV2/Batch/ PermissionDelegationV1_1/DynamicMPT/fixBatchInnerSigs) the binary can't yet apply. …
- **fix(ffi): port shim build to rippled 3.2.0 — ed25519/secp256k1 now conan pkgs** (`7238d72`, xrpl-validator)
  3.2.0 moved ed25519/secp256k1 from external/ source builds to conan packages (targets ed25519::ed25519 / secp256k1::secp256k1, per rippled cmake/XrplCore.cmake). CMakeLists: drop dead external/-path IMPORTED targets -> find_package + conan targets. build.rs: drop manual ed25519/secp256k1 link lines (collect_conan_libs resolves them).
- **fix(ffi): migrate shim from namespace ripple to xrpl for rippled 3.2.0** (`6ef2393`, xrpl-validator)
  3.2.0 completed the ripple->xrpl namespace rename across libxrpl/xrpld (no compat alias). Migrate the hand-written shim files (CallbackReadView/MinimalApp/ MutationCollector + xrpl_shim.cpp): namespace decls + all ripple:: qualifiers -> xrpl.
- **fix(ffi): adapt CallbackReadView to rippled 3.2.0 ReadView interface** (`c166a21`, xrpl-validator)
  info()->header() (LedgerInfo->LedgerHeader); sles_type/txs_type renamed SlesType/ TxsType; balanceHook split into balanceHookIOU/MPT/SelfIssueMPT (non-pure) + ownerCountHook non-pure -> drop no-op overrides; digest() now pure -> throw-stub.
- **fix(ffi): repath MinimalApp includes + digest type for 3.2.0 libxrpl/xrpld reorg** (`99c45d6`, xrpl-validator)
  3.2.0 moved headers from xrpld/ into libxrpl: HashRouter.h xrpld/app/misc->xrpl/core; LoadFeeTrack.h xrpld/app/misc->xrpl/server; Ledger.h xrpld/app/ledger->xrpl/ledger. CallbackReadView::digest now returns std::optional<uint256> (digest_type alias not member-accessible). Application/Config/OrderBookDB stayed in xrpld.
- **fix(ffi): rewrite MinimalApp for 3.2.0's 16-virtual Application + shim fixes** (`7e13344`, xrpl-validator)
  3.2.0 slimmed Application to 16 pure virtuals (lifecycle + config/nodeIdentity/etc; heavy service accessors gone). Rewrote MinimalApp to implement exactly those 16 (config() real w/ networkId; rest stub-throw), dropping ~35 obsolete overrides + the hashRouter/loadFeeTrack/orderBookDB/logs members — which also clears the io_service, PathRequests, OrderBookDB-incomplete, setup_HashRouter, beast::severities, and …
- **fix(ffi): MinimalApp implements all 46 ServiceRegistry virtuals + xrpl_shim 3.2.0** (`6b77e3c`, xrpl-validator)
  3.2.0 moved the service accessors into a ServiceRegistry base (46 pure virtuals). MinimalApp now implements all 62 (16 Application + 46 ServiceRegistry): config() real (networkId); isStopping/getApp/getJournal(null sink)/getTrapTxID kept safe so apply-path lifecycle/logging calls don't throw; the rest are throw-stubs (shadow window will reveal any apply actually needs — e.g. …
- **fix(ffi): beast::Severity enum values are Fatal/Error (not kFatal/kError)** (`1ecb3f5`, xrpl-validator)
- **feat(validator): API bind port is FFI_PORT-configurable (default 3777)** (`92ca532`, xrpl-validator)
  Lets a shadow/test instance run beside the live validator on a different port (FFI_PORT=3787); production unchanged (default 3777).
- **fix(ffi): MinimalApp::getNetworkIDService real (NetworkIDServiceImpl) for 3.2.0** (`15f602f`, xrpl-validator)
  The shadow showed every FFI apply throwing tefEXCEPTION 'MinimalApp::getNetworkIDService — not implemented'. 3.2.0 preflight routes the tx NetworkID check through getNetworkIDService(); implement it like the real Application: make_unique<NetworkIDServiceImpl>(config.networkId).
- **fix(ffi): make getHashRouter/getFeeTrack/getOrderBookDB/getLogs real for 3.2.0** (`db47945`, xrpl-validator)
  Port the <=3.1.x shim's real service impls to the 3.2.0 MinimalApp: HashRouter (setup_HashRouter + stopwatch), LoadFeeTrack (null journal), OrderBookDB(*this), and Logs(Fatal) that OrderBookDB needs. The apply()/preflight() chain reaches these for regular tx types; previously throw-stubbed -> every live-apply hit tefEXCEPTION (getHashRouter). Signing path is unaffected (independent of FFI).
