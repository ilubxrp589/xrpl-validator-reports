### Other engineering changes

- **feat(node): Stage 4 Phase B — the native Rust engine writes state.rocks (XRPL_NATIVE_WRITER=1)** (`4adb4a8`, xrpl-validator)
  On 2026-10-08 the network enabled PermissionDelegationV1_1. libxrpl 3.4.0 refused those transactions (temDISABLED); under Stage 3 its overlay was what got written, so #107525002 failed the state hash three times and the validator halted, while the native engine had applied them exactly as mainnet did.
- **feat(scripts): watch_engine says who writes state.rocks under the native writer** (`5b6c81f`, xrpl-validator)
  Under XRPL_NATIVE_WRITER the dashboard now has a "WHO WRITES THE LEDGER DATABASE" block: the Rust engine ACTIVELY WRITING (or LOADING, or OFF on the breaker), libxrpl COMPARING ONLY, and xrpld the reference node as the data feed plus the ledgers our engine could not vouch for. The FFI panel is titled COMPARISON ONLY, the native panel ACTIVELY WRITING / LOADING / WRITER OFF, and the writer's share counts ledgers since its copy of …
- **feat(tools): xrpl-watch, the validator's terminal dashboard in Rust (HALCYON)** (`d354cf0`, xrpl-validator)
  A ratatui successor to scripts/watch_engine.py, run beside the validator: `tools/xrpl-watch`, its own workspace so the validator's build and lock never see its dependencies.
- **feat(tools): xrpl-watch shows every transaction type and result code** (`45ca52a`, xrpl-validator)
  The C++ panel lists the types and result codes since start, as many as fit in two lines each, ending "+N more · t". The t key opens a page with every type and every result code, counts and log-scaled bars (one tx is still visible next to forty thousand), tes / tec / other coloured apart; t again returns. --view types renders that page with --once and --record.
- **feat(tools): xrpl-watch lists every type and result on the main screen** (`e53ce35`, xrpl-validator)
  James: take out the event feed (or really reduce it) and the t page. The bottom row is now EVERY TX TYPE and EVERY RESULT CODE since the validator started, packed in columns with a log-scaled magnitude glyph per entry, plus THIS LEDGER; long names are shortened (Permissioned -> Perm, …) before eliding. The event feed is one line, the newest event. The t page, the c key and --view are gone.
- **feat(tools): xrpl-watch in real time — ~30 fps, the validator read 4x a second** (`b945ba2`, xrpl-validator)
  James: "1 second refresh is fast but can seem kind of choppy". The screen now redraws at ~30 fps and reads the validator's API every 0.25 s (the upstream every 1 s, the process scan every 5 s, amendments every minute, the receipts file only when it changes). Between reads it animates: the counters roll to their new values, the pulse is a real-time trace (each ledger a beat where it closed, scrolling left and fading, …
- **feat(tools): xrpl-watch --record --fps, and a real-time footer** (`c86e5e0`, xrpl-validator)
  --record takes --fps F: frames F times a second while the data is still read every --interval (the walkthrough video records 15 fps, reads 4x a second). The footer says what the screen now does: real time, ~30 fps, the validator read 4x a second.
