### Other engineering changes

- **fix(ledger): the POOL can activate a strand, and an active strand reaps** (`6e631e7`, xrpl-validator)
  rippled filters strands on `qualityUpperBound` — an OPTIMISTIC bound on what the strand could conceivably do (StrandFlow.h:696-699, `qualityUpperBound(sb, *strand) < *limitQuality => continue`). For a book with an AMM that bound includes the pool. A strand whose every BOOK level is worse than the limit therefore still gets built, its offer stream still steps, and the dead offers it steps past are still reaped — even …
- **feat(ledger): reverse pass — size each payment hop to what the next needs** (`9ac6bcc`, xrpl-validator)
  rippled flows a strand in TWO passes: a REVERSE pass walking back from the requested output working out how much input each step needs (StrandFlow.h:105-230, `for (auto i = s; i--;) strand[i]->rev(...)`, re-executing a limiting step when one binds), then a FORWARD pass bounded by what is actually available. Ours was forward-only, so an intermediate hop sold its WHOLE carry rather than buying what the hop after it …
- **feat(ffi): capture libxrpl's decision trace under XRPL_FFI_TRACE** (`8b5a197`, xrpl-validator)
  The shim already had a CapturingSink wired into xrpl_apply_with_mutations and surfaced through xrpl_result_last_fatal — but gated at Severity::Fatal, so everything rippled narrates was thrown away. Lift it to Trace when XRPL_FFI_TRACE is set, and dump it per transaction with XRPL_FFI_TRACE_TX=<hash prefix>. Both OFF by default: gate runs stay byte-identical and trace capture is neither free nor small.
- **fix(ledger): round a fill's XRP input by which side bounds it** (`d6f7589`, xrpl-validator)
  The taker's input was always ceiled to whole drops. rippled's direction depends on which side of the fill is fixed — its rev/fwd split: - the taker's remaining WANT bounds it: the input is computed FROM that output (`rev`) and rounds UP, so the taker pays enough; - the maker's FUNDING bounds it: the output is what is fixed and the input follows it (`fwd`), rounding DOWN.
- **fix(ledger): judge a fill's achieved quality exactly, as rippled does** (`133fd89`, xrpl-validator)
  rippled discards a pass outright when the quality it actually realised misses the limit: if (limitQuality && q < *limitQuality && (!adjustedRemOut || !withinRelativeDistance(q, *limitQuality, Number(1, -7))))
- **fix(ledger): one AMM turn per pass, and a rejected pass ends the crossing** (`8152aca`, xrpl-validator)
  Three pieces, each only visible once the previous one landed, all read off libxrpl's own trace rather than inferred.
