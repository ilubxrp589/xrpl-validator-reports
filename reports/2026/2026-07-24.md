## Engineering changes

- **fix(xrpl-ledger): CheckCash requires exactly one of Amount / DeliverMin** (`609c827`, xrpl-validator)
  Preflight required Amount, so it rejected every DeliverMin cash-out as temMALFORMED — a valid transaction the network accepts, which is a consensus-relevant divergence (we'd drop a tx mainnet applies). rippled's rule is an XOR: bool(Amount) == bool(DeliverMin) => temMALFORMED (CheckCash.cpp:57). Amount is a fixed cash-out; DeliverMin a floor for a partial one.
- **fix(xrpl-ledger): a Payment to a pseudo-account is tecNO_PERMISSION** (`3a718aa`, xrpl-validator)
  An AMM, Vault, or LoanBroker account receives value only through its own transaction type — never an ordinary Payment. rippled rejects it with tecNO_PERMISSION (Payment.cpp:635, isPseudoAccount(sleDst)), where a pseudo-account is any AccountRoot carrying a designator field: sfAMMID, sfVaultID, or sfLoanBrokerID. The engine had no such check and delivered.
- **fix(xrpl-ledger): OfferCreate crossing spends only accountFunds, not TakerGets** (`1de6d87`, xrpl-validator)
  rippled clamps the crossing input to the taker's actual funds -- "Don't send more than our balance", OfferCreate.cpp:399-401, where inStartBalance = accountFunds(psb, accountID_, takerAmount.in, ...) is the XRP balance minus reserve. TakerGets bounds what may REST, never what may be spent. We clamped only at TakerGets, so an underfunded offer crossed with money the account did not have.
- **fix(xrpl-ledger): honour keepRoot when a directory page empties** (`34fca11`, xrpl-validator)
  dir_remove always deleted an emptied root page -- rippled's keepRoot=false behaviour -- with no way to ask for anything else. Most owner-directory removals pass true, so we emitted the page as Deleted (:2) where mainnet emits it Modified (:1).
- **fix(xrpl-ledger): CheckCancel unlinks the Check from both owner directories** (`b79f40f`, xrpl-validator)
  A Check is linked into TWO owner directories -- the writer's via sfOwnerNode and the destination's via sfDestinationNode. CheckCreate inserts both (check.rs) and CheckCash removes both, but CheckCancel removed neither: it deleted the object and adjusted the reserve, leaving two dangling directory entries.
