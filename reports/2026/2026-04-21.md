### Other engineering changes

- **fix(ffi_engine): OverlayedDbProvider::succ() must consult overlay, not just snapshot** (`69bc726`, xrpl-validator)
  The previous implementation iterated only the RocksDB snapshot, so when an earlier transaction in the same ledger modified or deleted an SLE in a directory the current transaction walks (Offer-book traversal in particular), libxrpl saw a stale RocksDB neighbor and crossed wrong offers. Cascade: wrong mutations -> wrong sequence -> tefPAST_SEQ on downstream transactions from the same accounts.
- **fix(ffi_engine): tefBAD_LEDGER recovery — fetch missing SLE and retry apply** (`6dd8f22`, xrpl-validator)
  When AccountDelete walks the deleted account's owner directory, libxrpl FFI returns `tefBAD_LEDGER` with a fatal message like: "DeleteAccount: directory node in ledger N has index to object that is missing: <64-hex-key>" meaning state.rocks is missing an SLE referenced by the owner dir (bulk_sync / ws_sync completeness gap). Historically these divergences also cascaded: 100% of observed Payment terPRE_SEQ …
- **feat(dashboard): /logs page — progress journal + live GitHub changelog** (`8176931`, xrpl-validator)
  Adds a new /logs route with two tabs: - PROGRESS — hand-written narrative sourced from PROGRESS.md at the repo root. Read at request time via fs.readFileSync so edits to the markdown show up without a rebuild. Clearly labeled as manually-curated.
- **fix(ffi_engine): loop tefBAD_LEDGER recovery for multi-missing-SLE owner dirs** (`4ab09ec`, xrpl-validator)
  The single-try recovery shipped in 6dd8f22 handles AccountDeletes with exactly one missing SLE in the owner directory. When the dir references multiple missing SLEs (NFTokenOffers + Offers + RippleStates on an old high-activity account), the first retry injects SLE #1 but libxrpl then trips on SLE #2 and returns tefBAD_LEDGER again.
