## Engineering changes

- **fix: correct repository URL in all Cargo.toml files** (`4417b88`, xrpl-sdk)
  Update repository field from placeholder xrpl-rust org to actual ilubxrp589 account. Fixes docs.rs links, crates.io metadata, and cargo tree output.
- **fix(core): update thread_rng() to rng() for rand 0.9 compatibility** (`fb7a327`, xrpl-sdk)
  rand 0.9 renamed thread_rng() to rng().
- **feat: initial scaffold — xrpl-ledger and xrpl-node crates** (`4299395`, xrpl-validator)
  Two-crate workspace for building an XRPL validator node in Rust: - xrpl-ledger: SHAMap, NodeStore trait, ledger header/objects/state (module stubs + error types, depends on xrpl-core via git) - xrpl-node: peer protocol, consensus, mempool, RPC server (module stubs + config + error types, protobuf codegen from rippled's xrpl.proto, tracing framework)
- **feat(node): node identity, message types, and wire codec** (`07c32fd`, xrpl-validator)
  - peer/identity.rs: NodeIdentity with Ed25519 keypair, self-signed TLS cert (pubkey in CN), rustls server/client configs, AcceptAnyCert verifier for self-signed peer network (4 tests) - peer/message.rs: PeerMessage enum wrapping all 21 protobuf message types with encode/decode dispatch by type code - peer/codec.rs: MessageCodec implementing tokio-util Decoder/Encoder with 4-byte length prefix, 2-byte type code, zlib …
- **feat(node): handshake, connection, peer lifecycle** (`d92281f`, xrpl-validator)
  - peer/handshake.rs: outbound XRPL/2.0 handshake over TLS — HTTP upgrade with Public-Key, Session-Signature (TLS exporter keying material), Network-ID, Crawl headers. Supports mainnet/testnet/devnet. - peer/connection.rs: async read/write loops via tokio select!, auto ping/pong handling, overlay message forwarding, graceful shutdown via watch channel. PeerHandle for sending messages to peers. PeerInfo tracks pubkey, …
- **feat(node): complete M1 peer protocol — live testnet handshake working** (`ebbb373`, xrpl-validator)
  Major milestone: successfully handshake with XRPL testnet and decode peer protocol messages.
- **fix(node): M1 audit fixes — remaining bytes, docs, codec safety** (`140d13d`, xrpl-validator)
  Fixes from peer protocol audit: 1. CRITICAL: Pass remaining_bytes from handshake through to connection's codec buffer. The HTTP header read may consume bytes belonging to the binary protocol — these must be prepended to the Framed decoder's buffer.
- **fix(codec): correct frame length interpretation — messages now decode** (`12f9941`, xrpl-validator)
  The 4-byte length field in XRPL peer protocol frames is the protobuf payload size ONLY — it does NOT include the 2-byte type code.
- **feat(node): live XRPL peer message viewer on port 3777** (`e9613c4`, xrpl-validator)
  Web dashboard streaming real-time decoded XRPL peer protocol messages from the testnet via Server-Sent Events.

  Each validator is now tracked individually during consensus: - Proposals: extract node_pub_key from TMProposeSet, dot turns blue - Validations: extract SigningPubKey from serialized validation blob by scanning for field code 0x73 0x21, dot turns yellow - Consensus reached (ACCEPTED): all active dots flash green

  Full-screen validator agreement visualization: - Big ledger counter (Orbitron 48px, blue flash on close) - Phase indicator: PROPOSING → CLOSING → VALIDATING → CONSENSUS - Validator grid: 16x16px nodes that light up as they participate - Idle (dark) → Proposed (blue) → Validated (yellow) → Agreed (green) - Tooltip on hover shows validator key prefix - Stats: proposals, validations, unique validators seen, close …
- **feat(viewer): nebula background, physics orbs, rainbow consensus** (`853e04e`, xrpl-validator)
  Complete consensus page redesign: - Animated nebula background (5 drifting gradient blobs, 80px blur) - Force-directed validator orbs with orbital spin, gravity, repulsion - State effects: proposed (blue burst), validated (yellow shockwave), agreed (green explosion + outward blast + gravity pull-back) - Rainbow particle explosion on consensus: 80 HSL-cycling particles from center + 12 per agreed node, with glow …
- **feat(node): complete M3 transaction engine with live sig verification** (`604c1c1`, xrpl-validator)
  Full transaction validation pipeline with codec integration (audited): mempool/validate.rs: - Decode tx blob via xrpl-core binary codec - Extract Account, Fee, Sequence, LastLedgerSequence from decoded JSON - Signature verification: re-encode for signing, compute signing hash - Ed25519: verify against raw STX\0||bytes (Ed25519 does internal hash) - Secp256k1: verify against SHA512Half(STX\0||bytes) - Fee sanity …
- **feat(node): complete M4 consensus engine (audited)** (`bf78b0a`, xrpl-validator)
  Full RPCA consensus implementation: - unl.rs: Trusted validator list, manifest key rotation - state.rs: Open/Establish/Accept state machine with stability check - threshold.rs: Dynamic convergence 50%→60%→70%→80%→95% - close_time.rs: Resolution rounding, mode voting - validation.rs: Per-ledger validation tracking, >=80% fully-validated - proposal.rs: Transaction set hash (single source, re-exported) - …

  Final milestone — all 40 taskboard cards implemented and audited.
