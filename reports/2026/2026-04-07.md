### Other engineering changes

- **feat(ffi): Stage 2 — shadow state hash from FFI mutations** (`1a7c435`, xrpl-validator)
  After FFI applies every tx in a ledger, the accumulated mutations (overlay) are now returned from apply_ledger_in_order. The caller can compute a "shadow" state hash by cloning the current FlatHasher, applying the overlay (Created/Modified/Deleted SLEs), and computing the Merkle root — then comparing it to rippled's account_hash.
- **fix(ffi): shadow hash must snapshot hasher BEFORE process_ledger writes — fixes double-apply mismatch** (`a2feb29`, xrpl-validator)
- **fix(ffi): merge protocol-level state changes into shadow overlay — covers singletons + pseudo-tx effects** (`bf46baf`, xrpl-validator)
- **fix(ffi): shadow hash uses RPC canonical node_binary — fixes serialization mismatch** (`1eaf2a1`, xrpl-validator)
- **fix(ffi): move singleton insertion before shadow hash — shadow overlay now covers all state changes** (`b9d476a`, xrpl-validator)
- **feat(ui): shadow hash counter on hero banner** (`3f51bb2`, xrpl-validator)
- **feat(ui): show shadow hash hex comparison on hero — ours vs network with match indicator** (`9efb8cc`, xrpl-validator)
- **fix(ffi): terPRE_SEQ recovery — fetch sender AccountRoot at current ledger to break cascade** (`c88e6a8`, xrpl-validator)
- **fix(ffi): skip shadow hash until 5 consecutive state-hash matches — prevents false mismatch during settle** (`915782c`, xrpl-validator)
- **feat: serve static HTML from disk — no rebuild needed for frontend changes** (`021d687`, xrpl-validator)
- **feat: network topology page (PCB style) + catch-all static route for future pages** (`e4f2140`, xrpl-validator)
