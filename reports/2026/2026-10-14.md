## Engineering changes

- **fix(meta): UInt64 fields compare by value; AccountDelete and the LP-token line delete the zeroed SLE (Step 2 record receipts, soak #47)** (`9bd3693`, xrpl-validator)
- **fix(meta): a Batch inner's record carries the earlier inners' threading for objects they created or it deletes (Step 2 receipts, soak #47)** (`c15899a`, xrpl-validator)
- **fix(meta): a Batch inner deleting what an earlier inner created keeps its final content; a deleted root page drops its links first (Step 2 receipts, soak #47)** (`850aec2`, xrpl-validator)
- **fix(order): salt our canonical order with the set a quorum of trusted validations accepted (sfConsensusHash), as rippled does; the ledger's own root only without one (3.3 shadow receipts #107652744/745/752)** (`01d5da5`, xrpl-validator)
- **fix(ffi): a Batch's expected mutation set folds in ledger order: a key one inner deleted and a later inner created again is a Modified, as libxrpl reports it (mutation_divergences #107636230 ×129, #107654753)** (`8cbf17f`, xrpl-validator)
- **fix(payment): an existing destination is written back as rippled's update(sleDst) marks it, so a threadOwners stamp before it gives its FinalFields (Step 2 receipt #107655399 3B2D251B5861)** (`de5fd94`, xrpl-validator)
- **fix(escrow): only EscrowFinish marks the destination's root written (rippled's update(sled)); a cancel leaves it threading-only (Step 2 receipt #107656021 1458D55C06B4)** (`dfda531`, xrpl-validator)
- **fix(account): AccountDelete lowers the deleted account's OwnerCount (and TicketCount) per removed object, as each nonObligationDeleter does, and no longer writes an NFT offer's Destination root back (update() audit)** (`eb0c569`, xrpl-validator)
- **fix(offer): line_adjust's default-state test reads only the sender's QualityIn/QualityOut, as rippleCreditIOU does (update() audit, outside the class)** (`56f2653`, xrpl-validator)
- **fix(amm): a withdrawal or clawback that empties the pool erases the AMM with the balance it had: deleteAMMAccountIfEmpty writes the new LPTokenBalance only when the AMM survives (Step 2 receipt #107662483 88C9F7289CD1)** (`a366749`, xrpl-validator)
- **fix(peers): a peer that hides its version is "hidden", not its first peer's version; the node names itself xrpl-rust-validator/0.4.0+<commit>** (`7a4bd78`, xrpl-validator)
  The peer page's crawler fell back to overlay.active[0].version when a node's /crawl had no server section. The three XRP Kuwait hubs (hubs.xrpkuwait.com) hide theirs and list us first, so they showed as "xrpl-rust-validator/0.1.0", our own name. version::crawl_label now keeps rippled numbers ("rippled-3.4.1"), keeps named builds as they are, and says "hidden" otherwise.
