### Other engineering changes

- **fix(step4): stage A names a PermissionValue as rippled's JSON does** (`e83a4f7`, xrpl-validator)
  rippled's JSON names a PermissionValue (STUInt32::getJson through Permission's names): a transaction type's code plus one, or a granular permission from 65537 on. The codec gives the number, so stage A's copy of a DelegateSet differed from the reference node's on mainnet #107804444 4A242D3BBE51: ours 28, the reference node's "NFTokenCreateOffer". respell now names it. The definitions file is read once for both respellings.
- **fix(validator): an empty ledger's transaction tree is ours, so 5a can sign it** (`61be1f3`, xrpl-validator)
  check_ledger returned no tree for a ledger with no transactions, so our own hash borrowed its transactions (and its order, which the native order never judges for an empty set). Under 5a, which signs only a ledger whose every part is ours, an empty ledger could never be signed. On mainnet the network resumed after the 21 Oct stall with six empty ledgers, #107806253-258, and the validator signed none of them, though …
