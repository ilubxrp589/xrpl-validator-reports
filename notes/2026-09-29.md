- **Finding F407 (a trust line whose only setting is the default quality).** At ledger 107,311,328 an account sent a
  TrustSet on a CNY trust line, setting the limit to 0, setting NoRipple and clearing freeze. Afterwards the line held no
  balance, the account's limit was 0, and NoRipple is that account's default (it does not enable DefaultRipple); the
  only other thing stored for its side was an incoming quality of 1,000,000,000. That value,
  QUALITY_ONE, is a rate of exactly 1, the same as no quality at all, and rippled's TrustSet treats a stored
  QUALITY_ONE as zero before deciding whether either side still has an interest in the line. Neither side did, so
  mainnet deleted the line: the line and the issuer's directory page went, the account's directory page shrank, and
  the account's owner count fell from 1 to 0. The engine counted any non-zero stored quality as an interest and kept
  the line. It now treats a stored QUALITY_ONE as no quality, as rippled does. The mainnet transaction is pinned as a
  regression vector. Fixed in e1140ef.
- **Finding F408 (AMM deposit: the minimum is not the amount issued).** At ledger 107,314,214 an account deposited
  1.021192 XRP into an XRP/token AMM pool as a single-asset deposit, naming 56,639.2869999 LP tokens in the
  transaction's LPTokenOut field. In a single-asset deposit that field is only a minimum: rippled issues the LP tokens
  the deposited amount buys at the pool's price, and refuses the deposit (tecAMM_FAILED) only when that is fewer than
  the minimum. The XRP bought 57,211.40098 tokens, and mainnet issued 57,211.40098. The engine moved the same XRP but
  issued exactly the minimum, about 572 tokens short. It now issues what the deposit buys and refuses a deposit that
  falls below its minimum. The same code decided a second kind of single-asset deposit, in which the account names the
  tokens it wants: rippled issues that request rounded down to the precision at which the pool's total can record it,
  and the engine now does too (it issued the unrounded request). The mainnet transaction is pinned as a regression
  vector; the refusal and the rounding, which no mainnet transaction has exercised yet, are covered by unit tests.
  Fixed in 1fd1b9b.
